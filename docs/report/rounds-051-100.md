## 5.53 离线排队看得见 + 题库 356 题（第 50 轮 / 共 250 轮；50 轮打磨节点达成）

### 离线体验：排队的判定不再隐身

以前断网判定只靠顶部徽标里一句「待同步 N 条」，剩下什么都没有：不知道排的是哪几题、多少分，也没法手动推。现在：

- 顶部徽标：离线显示「离线 · 本地判定（待同步 N 条）」，联网但还有排队时显示「在线（待同步 N 条）」；
- 提交历史上方新增待同步面板：逐条列出时间 / 题目 / 判定 / 分数（最多 8 条），并写明「离线判定已完成，恢复网络后自动并入进度」；
- 新增「立即同步」按钮：有待同步记录时才出现，点一下**直接去试**（不看在线标志位——浏览器没触发 online 事件、或只是服务端刚起来时，标志位会骗人），成功就说同步了几条，失败会区分「还是离线」与「服务端没收」。

顺手修掉一个命名坑：同步函数原来叫 syncNow，而按钮 id 也是 syncNow——id 会在 window 上生成同名全局，读代码时容易把函数和 DOM 元素看混，改名 flushQueueNow。

## 5.55 判定历史可复盘 + 题库 380 题（第 52 轮 / 共 250 轮）

### 判定体验：历史从「只能看」变成「能拿回来改」

提交历史原来只是一张只读表。这轮：

- **点命令填回输入框**：每行命令都是按钮，点一下把那次提交的命令填进输入框并聚焦，提示写明「已把 09-26 10:05 那次提交的命令填回输入框，改完直接判定」。复盘时最常见的动作就是「那次差在哪，我改一下再判一次」。
- **带条数统计**：面板第一行给出「共 N 条　通过 X　未通过 Y」，筛选（全部/只看未通过/只看通过）跟着一起变；
- 没有存命令的旧记录明确显示「（未存命令）」，不再是一格空白。

实现上用事件委托接住点击（历史表随筛选重绘，逐行绑事件会随重绘丢），并按行号从内存里的 historyRows 取原文，避免把命令原文塞进 HTML 属性做转义体操。

### 顺手修掉一个真 bug：切题不刷新历史

历史接口是按当前题过滤的（/api/history?taskId=...），但 goToTask 从来没调用 loadHistory——于是切到另一道题，右栏还显示上一题的历史；
初始题没有记录时更是直接显示「还没有提交记录」，让人以为历史功能坏了。改法：在 goToTask 里补上 loadHistory()。

（这个 bug 是这轮实测踩出来的：先灌 3 条历史再切题，面板一直是空的；顺着「是数据问题还是刷新问题」查下去，发现接口返回正常、只是没人去拉。）

## 5.56 进度计划完成情况：读得出来、写得下来（第 53 轮 / 共 250 轮）

这轮不加功能点，专门解决「进度和计划完成情况怎么记录、怎么输出」——之前所有进度都散在完成报告里，人要看只能从头翻。

### 学习侧：plan --status（计划 vs 实际）

原来 plan 只能生成日程表，没人回答「这个计划我做到哪了」。新增：

- `node src/cli.mjs plan --status [--hours=2] [--track=go] [--json]`：把计划里的每一天与真实提交记录对齐，输出整体完成度、整天完成数、

### 顺手修掉一个真缺口：Go / Rust 命令一条都抽不出来

`src/core/site-learn.mjs` 的工具识别表（TOOL_TRACK）只认 docker/kubectl/git/… 这些老轨道，**没有 go、cargo、make、helm、terraform、ss/ip/ssh、ab/wrk** 等，
于是从一个 Go 或 Rust 仓库解析草案时命令数直接是 0（我造夹具时才发现）。补齐到当前 24 条轨道，并顺手解决另一个常见坑：
`CGO_ENABLED=0 GOOS=linux go build …` 这类**带环境变量的命令**工具名不在行首，按行首匹配永远抓不到——现在会先剥掉前导 `VAR=value` 再认工具名。

### git 克隆：真拉过，也真失败过（都留证据）

- 顺手加了两条：克隆 2 分钟超时（超时给明确文案）、失败时**清掉半个目录**，不在项目里堆空目录。

### 立一条机器能查的不变式

2. 变体答案在**自己平台必须 100 分**；
3. 同一道题的**任意两个已声明平台之间必须互相判不过**（40 题 × 平台两两组合，实测 0 例外）。

写这条测试时先被它逮到两个真问题：一是 `git.autocrlf-cross-platform` 只声明了 win32 一个变体——
它其实是"基础 = mac/linux，Windows 单独覆盖"的合法写法，于是把规则改成"变体必须比基础更具体"，而不是生硬要求平台数 ≥ 2；

所以比较只在题目声明过的平台之间做，并把这条兜底写进测试注释，免得后来者当成 bug 去"修"。

## 5.72 真浏览器实测逮到两个真 bug：同步后徽标不擦、题号不能深链（第 69 轮 / 共 250 轮）

这轮把网页版重新放进真浏览器跑了一遍完整流程（清 SW 与缓存 → 离线作答 → 恢复网络 → 深链打开），逮到两个只有实测才会暴露的问题。

### Bug 1：同步成功后，页面上还挂着「待同步 N 条」

复现：断网 → 提交一次判定（进本地队列，徽标显示「离线 · 本地判定（待同步 1 条）」）→ 恢复网络。
记录**确实写进了服务端**（store 里两条记录都在，没有丢数据），但徽标与待同步面板依旧显示 1 条，用户只能刷新页面才看到真相。

根因在 `web/app.mjs` 的 online 事件处理里：它**先 renderNetBadge() 再 await flushQueue()**，画的时候队列还是满的，清空之后没人重画。
修法是在**根**上补，而不是在调用方各加一次：`flushQueue()` 是全仓唯一清空队列的地方，让它清空后自己重画，
所有调用方（自动同步、手动「立即同步」）自然都对了：

    await post('/api/import', { records: rows });
    writeQueue([]);
    renderNetBadge();   // 队列一变就重画：徽标、待同步面板、立即同步按钮都读队列

顺带给 test/page.test.mjs 加了一条正则断言：`flushQueue()` 里清空队列后必须紧跟重画，防止后来者再把它挪回调用方。

### Bug 2：题号不能深链（我自己踩到的）

测这轮的离线流程时，我按 `#task=go.buildinfo-extract` 打开页面，结果题面还是第一道题——地址里只认 `#project=`，题号被当噪声忽略。
对用户来说就是「没法把一道题发给别人」。补上：

- `readTaskHash()` / `setTaskHash()`，切题（`goToTask`）时同步写进地址；
- 抽出 `writeHash({...})`：开项目只改 `project`、选题只改 `task`，**互不抹掉**（原来的 setProjectHash 是整串覆盖）；
- `restoreTaskView()` 在 bootstrap 末尾恢复；目标题被当前筛选挡住（难度/状态/搜索）时先 `resetAllFilters()`，不做"打开了却看不见"的空动作。

### 浏览器实测（清掉 SW 缓存后的每一步都有记录）

| 场景 | 操作 | 结果 |

## 5.73 GitHub 导入真的能用：简写、镜像链、复用克隆、以及"是谁改写了我的地址"（第 70 轮 / 共 250 轮）

目标里第 2 条是「添加 github，git 克隆项目，解析涉及的知识点，并生成题目」。这条链路上最脆的一环是**拉代码**：

### 1. 认得出 owner/repo 简写

`learn-repo gin-gonic/gin` 现在等价于 `https://github.com/gin-gonic/gin`；本地目录、`https://`、`git@` 三种写法各归各的路线，

    注意：本机 git 配置把 https://github.com/octocat/Hello-World 改写成了

一直是服务端算的，但原生端此前拿不到——只能靠每日一题一天看一道。

### 原生端：复习队列

- `Engine.review(track:limit:)` 调 `/api/review`；`ReviewRow` 只声明用得到的字段，`dueDay` 把时间戳截到天（复习按天走）；
- `Store.loadReview()` 在**开窗、判定后、换轨道**时刷新；
- 右栏（还没判定时）显示复习区块：上次分数 + 理由 + 「复习」按钮，底下附一行「之后到期」；
- 跳转逻辑抽成 `Store.jump(to:)`，**每日一题与复习队列共用一份**——被当前筛选挡住时先清筛选再选中，
  免得出现「点了按钮却看不见那道题」（上一轮暴露过的坑，这次没有复制第二遍）。

### 一句更诚实的理由（三端共用）

自检里造了一条「3 天前没通过」的记录，界面给的理由却是**「该复习了（1 天前学过）」**——`intervalDays` 是节奏定的天数，
不是真实间隔，使用者只会以为自己记错了。改在**根上**（`reviewQueue` 一处，网页版表格 / 命令行 / 原生端都读它）：

    该复习了（已逾期 2 天）        // 迟到时说实话
    该复习了（今天到期）            // 正好当天
    还没到复习时间（还有 N 天）      // 未到期保留倒计时

## 5.82 真断网实测 + 外壳版本自检（第 79 轮 / 共 250 轮）

这轮把「离线体验」按最狠的方式验了一遍：**把服务端真的杀掉**，然后刷新页面。顺带逮到一个发版后才会出现的问题。

### 真断网（服务端进程被 kill）

| 检查项 | 实测 |
| --- | --- |
| 页面能否打开 | 能。Service Worker 用缓存的外壳起页面，`__dshPerf` 首屏列表 **10ms** |
| 题库从哪来 | 本地缓存的 bootstrap：**526 题**，页头明说「（离线：题库来自 2026-09-26 17:08:54 的缓存）」 |
| 在线状态 | 徽标「离线 · 本地判定」；每日一题显示「离线：每日一题需要连接服务端」而不是假装有数据 |
| 还能练吗 | 能：选一道题作答 → 本机 judge.mjs 判分（0 分，缺失项照常列出）→ 记录进本地队列 |
| 待同步面板 | 「待同步 1 条」，徽标同步变成「离线 · 本地判定（待同步 1 条）」 |
| 恢复网络 | 服务端重启 → 自动同步：队列 0 条、面板清空、徽标回「在线」，store 里能查到那条 17:09:27 的记录 |

结论：断网时**能看题、能练、能判、能排队**，恢复后自动补上——这正是「离线体验」该有的样子；唯一进不了的是需要服务端的数据（每日一题、只读验证）。

### 逮到的问题：发版后页面可能还在跑旧外壳

Service Worker 的缓存桶带版本号、并且是「先用缓存、后台刷新」的策略，所以：**发一次新版之后，用户刷新页面拿到的很可能仍是上一个版本的外壳脚本**
（实测：服务端已经是 0.45.2，页面桶还是 `dsh-learn-shell-0.45.1`，要等下一次打开才换）。页头版本号来自服务端，会显示新版本，于是这种不一致**在界面上看不出来**——
问题只在行为奇怪时才暴露（比如刚修的 bug 还在复现）。

改法：让外壳脚本**自己带版本号**，页面启动时比对。

1. `src/web/static.mjs` 在发送 `/app.mjs` 时把 `__VERSION__` 注入成真实版本（与 sw.js 同一套做法）；
2. 页面里 `const SCRIPT_VERSION = '__VERSION__'`；启动时若 `SCRIPT_VERSION !== 服务端 appVersion`，说明跑的是缓存里的旧外壳：
   让 Service Worker 立刻 `update()`，并**重载一次**取新外壳；
3. 只重载一次（用 sessionStorage 里的版本号当闸门）：如果 SW 没换掉，就不再反复刷新，而是在界面上直说
   「页面外壳仍是 X（服务端 Y）：按 ⌘⇧R / Ctrl+Shift+R 强制刷新即可」。

直接打开文件（file://）时占位符还在，比对会被跳过——不做事先没想清楚的自作聪明。

### 实测（模拟一次真实发版：0.45.1 → 0.45.2）

| 步骤 | 观察到的结果 |
| --- | --- |
| 干净建立外壳（0.45.1） | 缓存桶 `dsh-learn-shell-0.45.1`，`__dshSw.scriptVersion = 0.45.1`、staleShell = false |
| 服务端升到 0.45.2 并重启 | `/app.mjs` 注入 `SCRIPT_VERSION = '0.45.2'`、`sw.js` 桶名同步为 0.45.2 |
| 刷新（外壳仍旧） | 页面发现版本不一致 → 自动更新 SW → 重载一次 → 缓存桶变成 **`dsh-learn-shell-0.45.2`**，`seen`/`reloaded` 都记成 0.45.2，不再有强制刷新的提示 |

### 证据

- 真断网全链路：kill 服务端 → 刷新（10ms 起页面、526 题）→ 离线判定 → 队伍 1 条 → 重启服务端 → 自动同步（store 里查到该记录）

## 5.87 同一类 bug 的第二例：批量导入也被 64KB 顶回来（第 84 轮 / 共 250 轮）

### 先量：同一份记录，不同条数会被怎样对待

| --- | --- | --- |
| 200 条 | 36KB | 200 已导入 |

## 5.88 路径边界巡检：两个「能写到项目外 / 读到项目外」的口子（第 85 轮 / 共 250 轮）

这几轮在处理「请求体上限」这一类的边界问题，这轮换成**路径**：凡是把外部输入拼进路径的地方都试一遍。

### 先试安全的那些（确认设计没问题）

| 输入 | 结果 |
| --- | --- |
| `project init '../../evil'` | 落在 `projects/evil`（name 走 slug，`..` 与 `/` 被替换掉） |
| `project init '/etc/evil'` | 落在 `projects/etc-evil` |
| `project init '..'` | 落在 `projects/project`（slug 为空时的兜底） |

### 逮到两个真口子

**① `pack promote --into` 能写到仓库外。**实测 `--into=../../escaped.json`（不 dry-run）真的把文件写到了仓库上一层的目录里，

### 改法：一个「根内校验」工具，两个入口都用它

- `src/core/project.mjs` 新增 `withinDir(base, candidate)` 与 `safeBaseName(name)`：前者判断目标是否落在允许的根内，

- `promoteDraft` 的判定规则写清楚：给了 `baseDir`（网页版设成项目目录）就必须在里面；没给 baseDir 而 `--into` 是**相对路径**时以当前目录为根

## 5.92 性能实测后的一个小优化：brotli + 命令边界对齐（第 89 轮 / 共 250 轮）

题库涨到 545 题，先量一遍首屏成本，再决定改什么——不凭感觉优化。

### 量出来的数字（545 题）

| 项 | 数值 |
| --- | --- |
| /api/bootstrap 未压缩 | **444.1KB**（454824 字节） |
| gzip 后 | 127.5KB |
| 接口耗时（本机 curl） | bootstrap 3ms、progress 17ms、drill 3ms、daily 12ms、review 10ms |
| CLI 冷启动 `list` | 58ms |

结论：瓶颈不在服务端（毫秒级），而在**首屏要传的 JSON 体积**——本机感觉不到，但手机 PWA、局域网、远程 agent 都要吃这 127KB。

### 改动一：brotli 协商（同一份 JSON 再小两成）

Node 自带 brotli，不用装依赖：`sendSmart` 先看 `accept-encoding` 里有没有 `br`，有就用 brotli，否则退回 gzip。
实测同一份 bootstrap：**gzip 127.5KB → brotli 101.3KB（再省 21%）**；响应头 `content-encoding: br`、`vary: Accept-Encoding`、`content-length` 都对得上；
不支持压缩的客户端仍拿明文，几百字节的小响应照旧不压。

### 改动二：`learn-site --out` 与 `pack promote` 用同一套边界

上上轮修的是 `pack promote --into` 的相对越界写入。这轮把同类入口对齐：`learn-site --out` 之前能写任意路径，
现在**相对路径不许 `../` 爬出当前目录**（显式绝对路径仍放行，那是用户自己指定位置），而且这条检查**放在抓取之前**——
省一次白跑的网络请求，也让规则不依赖网络就能测。

### 证据

- 压缩实测：bootstrap gzip 130657 字节 → brotli 103682 字节（-21%）；`content-encoding`/`vary`/`content-length` 正确；小响应与不接受压缩的客户端行为不变
- 新增测试：compress 里一条「同时支持 br 时优先 brotli 且比 gzip 小」（对比两份真实响应体的 content-length）
- 新增测试：cli-commands 里一条「--out 相对越界在抓取前被拒、绝对路径放行」（不联网）
- 命令实测：`learn-site https://example.com --out=../../escaped-draft.json` → 立即报「--out 必须写在 … 之内」，仓库外无文件
- node --test **298/298**（新增 1 条 brotli 用例；--out 边界那两条断言加在已有的 analyze 用例里）；bash scripts/verify.sh **PASS 72 / FAIL 0**
